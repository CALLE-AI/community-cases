Local Atlas

Ask once. Share the answer. A map can tell you where a café is. A phone call can tell you whether there’s parking. Local Atlas turns that answer into a dated FAQ for the next visitor.

Workflow Reuse Evidence

A question worth sharing.

Local Atlas checks for a reusable answer first. When one is missing, CALL-E handles the phone conversation; the app checks and stores the result.

This walkthrough uses a fictional café and written example data. It does not place a call.

  1. 1

    Ask one factual question

    Choose a place with a listed phone number, then ask: “Is there parking on site?” For a real call, review the number and question before confirming.

  2. 2

    Save the evidence

    The assistant identifies itself as AI, asks the question and lets the staff member finish. A clear answer is saved with their words and a collection date.

    “Yes, we have a small customer lot out back.”

  3. 3

    Reuse the answer

    Someone opening the same place can read the shared FAQ. Asking the same question while its result is still valid reuses that result without another call.

Make it your own.

Start with one question, a short evidence quote and an explicit “unknown” outcome. Then decide how long that answer should remain useful.

A single-question prompt

Call {{business_name}} at {{phone_number}}.
Ask one question: “Is there parking on site?”

Let the staff member finish their greeting. Ask if it is a good moment for one quick question.
Before asking, say that you are an AI assistant calling for someone planning a visit.
If it is a bad time or they decline, thank them and end the call.
Ask only the stated question. If needed, ask at most one short clarification.
Never guess. Let them finish; then thank them and end the call.
Do not book, order, negotiate or collect personal or payment details.
If you reach voicemail or an automated menu, end without leaving a message.
Result schema

Keep the status separate from the answer. An unanswered question must stay unknown. The evidence quote must come from the staff member’s transcript.

{
  "type": "object",
  "additionalProperties": false,
  "required": ["answer_status", "answer", "evidence_quote"],
  "properties": {
    "answer_status": {
      "type": "string",
      "enum": ["answered", "unclear", "refused", "unreachable", "unknown"]
    },
    "answer": {
      "type": "string",
      "description": "Use only what the business said. Write exactly unknown unless answer_status is answered."
    },
    "evidence_quote": {
      "type": "string",
      "description": "A direct staff quote supporting the answer, or an empty string when no usable quote exists."
    },
    "staff_confidence": {
      "type": "string",
      "enum": ["certain", "hedged", "unknown"]
    }
  }
}

Try the full flow
on your machine.

The author’s review mode runs without a CALL-E key or an account. Dry run simulates the call and keeps the phone from ringing.

You’ll need Git, Node.js 20+ and npm. Place search still needs internet access.

Start a local simulation

git clone https://github.com/omarmiri/Local-atlas.git
cd Local-atlas
git checkout 0b1095d1ad02530f3aead96c01e523e24dfd1a55
npm install
REVIEW_MODE=1 CALLE_DRY_RUN=1 npm start
  1. Open localhost:10000. Search a US or Canadian town and open a place with a listed phone number.
  2. Open “Ask the Place” and choose a preset question. Review mode works when Supabase authentication is unconfigured.
  3. Wait for the simulated result, then ask the same question again to see the stored result reused. Outcomes can include an unclear answer or no answer.

These commands target the reviewed source version. The simulation skips the confirmation gate used for real calls. See the author’s setup guide for configuration.

Know these limits before you reuse it

  • Freshness needs care. Answered FAQs default to 90 days; other outcomes to one day. The current code does not shorten this by question type. Time-sensitive answers need a stricter policy.
  • Real calling needs setup. The app requires credentials, an access code, a callable number and explicit confirmation. Review mode and dry run do not validate that live path.
  • Start with a preset question. Custom questions depend on an external model for moderation. Place and phone coverage depend on the available data providers.
