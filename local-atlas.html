    Make it your own.

    Start with one question, a short evidence quote and an explicit “unknown” outcome. Then decide how long that answer should remain useful.

    Download the starter pack (.md) ↓

    Includes an adapted prompt, result schema, example data and local setup. Based on the author’s MIT-licensed implementation.

    Answered FAQs default to 90 days; other outcomes to one day. Choose a shorter expiry for time-sensitive questions, since the app does not adjust it by question type.

    A single-question prompt

    Call {{business_name}} at {{phone_number}}.
Ask one question: “Is there parking on site?”

Let the staff member finish their greeting. Ask if it is a good moment for one quick question.
Before asking, say that you are an AI assistant calling for someone planning a visit.
If it is a bad time or they decline, thank them and end the call.
Ask only the stated question. If needed, ask at most one short clarification.
Never guess. Let them finish; then thank them and end the call.
Do not book, order, negotiate or collect personal or payment details.
If you reach voicemail or an automated menu, end without leaving a message.
    Result schema

    Keep the status separate from the answer. An unanswered question must stay unknown. The evidence quote must come from the staff member’s transcript.

    {
  "type": "object",
  "additionalProperties": false,
  "required": ["answer_status", "answer", "evidence_quote"],
  "properties": {
    "answer_status": {
      "type": "string",
      "enum": ["answered", "unclear", "refused", "unreachable", "unknown"]
    },
    "answer": {
      "type": "string",
      "description": "Use only what the business said. Write exactly unknown unless answer_status is answered."
    },
    "evidence_quote": {
      "type": "string",
      "description": "A direct staff quote supporting the answer, or an empty string when no usable quote exists."
    },
    "staff_confidence": {
      "type": "string",
      "enum": ["certain", "hedged", "unknown"]
    }
  }
}

    Try the full flow
    on your machine.

    The author’s review mode runs without a CALL-E key or an account. Dry run simulates the call and keeps the phone from ringing.

    You’ll need Git, Node.js 20+ and npm. Place search still needs internet access.

    Start a local simulation

    git clone https://github.com/omarmiri/Local-atlas.git
cd Local-atlas
git checkout 0b1095d1ad02530f3aead96c01e523e24dfd1a55
npm install
REVIEW_MODE=1 CALLE_DRY_RUN=1 npm start
    1. Open localhost:10000. Search a US or Canadian town and open a place with a listed phone number.
    2. Open “Ask the Place” and choose a preset question. Review mode works when Supabase authentication is unconfigured.
    3. Wait for the simulated result, then ask the same question again to see the stored result reused. Outcomes can include an unclear answer or no answer.

    These commands pin the source version used in this guide. The simulation skips the confirmation gate used for real calls. See the author’s setup guide for configuration.

    For real calls, configure credentials and an access code, choose a callable number and confirm the request. Start with a preset question; custom questions need an external moderation model. Place and phone coverage depend on the data providers.
