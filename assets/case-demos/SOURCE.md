# Community workflow demonstrations

These four scenes, mock controls and fictional fixtures are original CALL-E editorial implementations of the workflows already documented in the case guides. They are not recordings or replicas of the authors’ applications. No application code or design asset from proprietary Care Call AI is redistributed. The individual guides retain their author links, licensing information and known limitations; those limitations still apply to the actual applications. The mock uses deliberately simple, deterministic choices, not the authors’ detection or answer-validation algorithms.

The native scenes reuse the site's official vendored Three.js 0.180.0 modules and existing playback controller. See ../local-atlas-demo/vendor/SOURCE.md and its retained MIT license. English text is native HTML. All shown people, messages, requests, restaurant responses and bookings are fictional; mock state is page-local and makes no calls or external submissions.

The active Conversation-Clarify, Care Call AI and HungryCall narration tracks were generated on 28 October 2026 with Microsoft Edge online TTS, voice `en-US-JennyNeural`, using `edge-tts` 7.3.1 and the upstream Lemo `tts_zh.py` helper bundled with Claude Motion. Each companion JSON records the unchanged script, voice parameters, segment timing and source/final hashes. Only the fictional narration text was sent for synthesis; the website serves local MP3 files without calling a speech service. Sound requires an explicit action; captions and transcripts remain available without audio or WebGL. The unused legacy RingBack audio retains its original ECNU provenance.

The scene geometry and absolute-time choreography for Conversation-Clarify, Care Call AI and HungryCall are in `stories.mjs`; `scene.mjs` owns rendering, responsive camera framing and context recovery. Each case has its own layout and actions. Phones follow articulated wrists; request and answer cards travel through clear foreground routes. Care retains two distinct request slots. RingBack uses `../ringback-demo/scene.mjs` for the world and `../ringback-demo/state.mjs` / `../ringback-demo/app.mjs` for a unified interactive flow. It no longer loads a narration track or a separate mock; manual choices and idle defaults call the same transition function. Its fictional diary screen is an original explanation, not a replica of the author’s application. HungryCall returns a match record, never a delivered parcel. No scene uses floating text over a character.

`timing.mjs` maps each narration’s phrase boundaries to the scene choreography and chapter previews. Conversation-Clarify and HungryCall use five speech segments; Care Call AI uses four. Silence is padded to the existing scene cues, with assertions that speech fits each interval before assembly; no spoken words are truncated or time-stretched. Local speech recognition verified the final transcripts. Narration downloads hold the opening frame, and subsequent playback controls cancel a pending narration start.

Scene checks sample the actual camera projection at 30 fps in desktop and narrow portrait aspect ratios, checking moving records against faces and viewport edges in addition to world-space clearance. HungryCall moves the returned match sideways before lowering it past the chef.

In the three shared scenes, official CALL-E SVGs appear on the active call relay and inside returned records. RingBack places CALL-E on the active call screen and waiting-list status. The shared scenes use depth-tested surfaces. RingBack uses compact native HTML controls beside the scene, moving them below it on narrow screens, so text stays readable and choices work with a keyboard. Record branding stays within the original card outline; relay geometry is included in face-clearance, viewport and solid-intersection checks.
