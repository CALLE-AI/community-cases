# Use Cases index

Mode: Read. Scope: `index.html`, its opening composition and page typography.

## Direction contract

THESIS: Help visitors understand a concrete CALL-E use case and find its demo or guide quickly. Navigation and introduction lead directly into the existing case collection.

OWN-WORLD: Preserve the official CALL-E wordmark, Use Cases name, existing miniature scene illustrations, case facts and links. A continuous neutral page ground lets those illustrations carry the yellow-and-blue character. Use the locally hosted Geist font consistently across this index; case detail pages keep their existing styles.

FIRST VIEWPORT: A compact header aligns with the content grid. The title and explanatory copy share a desktop row, followed immediately by Hackathon winners and the first illustrated case. On narrow screens the introduction stacks naturally. There is no full-width yellow banner, duplicate category badge or noninteractive blue title underline. Use Cases remains visible beside or beneath the logo.

INTERACTION: Preserve native demo and guide links, visible keyboard focus, relative case URLs and the footer destinations. The website link is secondary to discovering cases. Add no animation, carousel or new control.

## Method and evidence

The user rejected the white/yellow/white bands and clarified that Apple Design is a methodology reference, not a page-layout template. Apply the following principles to this existing website:

- [Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles): prioritize purpose, clear structure and useful content; retain the case illustrations as product-specific expression.
- [Layout](https://developer.apple.com/design/human-interface-guidelines/layout): use alignment, proximity and reading order for hierarchy; let layouts adapt to available width and larger text.
- [Color](https://developer.apple.com/design/human-interface-guidelines/color): keep color meanings consistent; reserve blue for links and focus rather than decorating a static heading.
- [Typography](https://developer.apple.com/design/human-interface-guidelines/typography): use a coherent type family, readable weight and a clear scale.

These are web design decisions informed by HIG, not a claim of Apple certification or a direct translation of native-platform measurements. No Apple artwork, fonts or page composition is copied.

## Verification boundary

Check the full index on desktop and narrow browser viewports, its first-case entry position, all original case destinations, keyboard focus, larger text and color contrast. Browser checks do not establish phone hardware or screen-reader acceptance. Publishing requires the user's approval.
